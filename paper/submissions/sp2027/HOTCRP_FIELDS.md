## Ethics Considerations

All personal data in this work is synthetic. The names, email addresses (example.org /
example.com domains), phone numbers (unassigned 555 area code), and Social Security
numbers (219-09-9999 and 123-45-6789, long-published invalid example values) were written
by the authors for the experiments. No real person's data was collected or processed and
no human subjects were involved, so IRB review was not required.

No live or third-party system was attacked. The two prompt-injection inputs were sent
only to the authors' own local serving process running an open-weight model (Qwen3-0.6B)
on their own CPU host. No hosted model API, production deployment, or third-party
service was queried or probed.

Dual use: the system encrypts PII in an LLM's output stream. The same mechanism could be
misused to hide exfiltrated data from output monitoring or data-loss-prevention tools,
since a monitor sees only ciphertext. The paper (Appendix A) discusses this and the
mitigations the design offers: a fixed, detectable seal grammar with visible entity type
and length; grounded sealing, which seals only values already present in the request's
inputs and lets a key-holding auditor verify that; and recommendations to log seal counts
in plaintext, escrow keys with the security team, and audit key access like record
access. An attacker who fully controls the serving host can already encrypt arbitrary
output, so the work does not add that capability. The paper also warns against treating
a sealed endpoint as "PII-free", because the detector covers only four structured types.
The implementation will be released open source (Apache-2.0); it contains no exploit
against any third-party product.

## Generative AI usage considerations

Object of study: the open-weight LLM Qwen3-0.6B is the untrusted generator whose token
stream the proposed system seals. A generative model is necessary because the paper's
subject is PII leakage in LLM streaming output. It was run locally on an 8-vCPU CPU host
with greedy decoding; we chose the smallest model in the family to minimize compute and
energy (each run is about 1 s of generation; the paper uses three end-to-end checks, five raw and five sealed timing runs, and four example prompts) and
because the mechanism is independent of model size. Weights are public and all prompts,
outputs, and timings are stored as artifacts, so results are reproducible. Limitation: a
0.6B model makes reasoning errors (one arithmetic error is reported in the paper); these
are the model's and are not affected by sealing. No model was trained or fine-tuned and
no data was collected for training.

Manuscript preparation: Generative AI was used for editorial purposes in this manuscript,
and all outputs were inspected by the authors to ensure accuracy and originality. All
ideas, the design, implementation, experiments, and literature review were developed and
validated by the authors; every number in the paper is generated by scripts from stored
artifacts.
